# 数据库备份和恢复

数据是唯一资产，**务必定期备份**。本文覆盖本地 SQLite 与线上数据库两种场景。

## 1. 本地 SQLite 备份

项目自带脚本 `scripts/backup_db.py` / `scripts/restore_db.py`：

```bash
# 备份：复制 backend/chenji_hub.db 到 backups/（时间戳命名）
python scripts/backup_db.py

# 只保留最近 30 份，自动清理更旧的
python scripts/backup_db.py --keep 30

# 查看现有备份
python scripts/restore_db.py --list

# 用最新备份恢复（会先确认，恢复前自动给当前库留底）
python scripts/restore_db.py

# 用指定备份恢复，跳过确认
python scripts/restore_db.py --backup chenji_hub_20260810_120000.db --yes
```

> `backups/` 目录已在 `.gitignore`，不会提交 GitHub。建议配合计划任务每天自动执行：
> - Linux / macOS：`crontab -e` 加 `0 3 * * * cd /path/to/project && python scripts/backup_db.py`
> - Windows：任务计划程序定时运行 `python scripts/backup_db.py`

## 2. 线上 PostgreSQL 备份

### 方式 A：平台自带备份（推荐）

如果线上用 Render PostgreSQL，控制台（数据库面板 → Backups）自带自动备份，**建议开启**。可配置每日备份与保留周期。

### 方式 B：pg_dump 手动导出

```bash
# 导出整库为压缩文件
pg_dump "$DATABASE_URL" | gzip > chenji_hub_$(date +%Y%m%d_%H%M%S).sql.gz
```

### 方式 C：Docker volume 快照

如果线上用 SQLite + Docker volume（`docker-compose.server.yml` 默认），备份 volume：

```bash
# 停止后端，拷贝 volume 数据（示例）
docker run --rm -v chenji-learning-hub-fullstack_chenji_data:/data -v "$PWD/backups":/backup \
  alpine tar czf /backup/chenji_data_$(date +%Y%m%d).tar.gz -C /data .
```

> volume 名可用 `docker volume ls` 查看（通常是 `项目目录名_chenji_data`）。

## 3. 恢复注意事项

- **恢复前先备份当前库**：防止把好的数据覆盖掉。
- **确认环境**：本地恢复用本地脚本；线上恢复要在服务器上对线上数据库操作，不要混用。
- **恢复后重启后端**：让连接池使用恢复后的数据。

## 4. 建议的备份策略

| 数据 | 频率 | 保留 |
|---|---|---|
| 本地 SQLite | 每天（或每次大改前） | 最近 30 份 |
| 线上 PostgreSQL | 每天（平台自动备份） | 按平台配置（建议 7~14 天） |
| 部署大版本前 | 手动备份一次 | 永久保留 |
