# 数据库说明

Chenji Learning Hub 的文章、计划、用户信息都保存在**数据库**里，不依赖浏览器 localStorage。

## 1. 数据源：SQLite（本地） / PostgreSQL（线上）

| 环境 | 数据库 | 连接方式 |
|---|---|---|
| 本地开发 | SQLite 文件 `backend/chenji_hub.db` | `DATABASE_URL=sqlite:///./chenji_hub.db` |
| 线上部署 | PostgreSQL（或 Docker volume 里的 SQLite） | `DATABASE_URL=postgresql://...` 或 `sqlite:////app/data/chenji_hub.db` |

后端用 SQLAlchemy，ORM 层与数据库无关，切换只改 `DATABASE_URL` 一个环境变量。

## 2. 数据表

| 表 | 说明 | 关键字段 |
|---|---|---|
| `articles` | 文章 | `id`、`title`、`summary`、`content`、`category`、`tags`(JSON)、`status`(draft/published)、`created_at`、`updated_at` |
| `plans` | 每日计划 | `id`、`date`(唯一)、`title`、`goal`、`morning`、`afternoon`、`evening`、`review`、`status`、`created_at`、`updated_at` |
| `users` | GitHub 登录用户 | `id`、`github_id`(唯一)、`username`、`name`、`avatar_url`、`created_at` |

> 没有浏览量 / 点赞 / 评论字段——项目刻意不生成假浏览量、假点赞、假评论，只保留真实内容。

## 3. 表结构的创建

后端启动时 `Base.metadata.create_all()` 自动建表（`backend/app/main.py`）。已存在的表不会重建，也不会自动加列；需要改表结构时先备份数据库，再手动迁移（后续可引入 Alembic）。

## 4. 文章可见性

- `status=published`：访客可见。
- `status=draft`：只有管理员（带 token）可见，访客访问返回 404（不泄露存在）。

## 5. 计划按日期定位

`plans.date` 是唯一索引，一天最多一条计划。接口按日期增删改：

```text
GET    /api/plans                计划列表
GET    /api/plans/{date}         某天计划（YYYY-MM-DD）
POST   /api/admin/plans          新增（同一天已有返回 409）
PUT    /api/admin/plans/{date}   编辑（可挪日期，目标被占返回 409）
DELETE /api/admin/plans/{date}   删除
```

## 6. 本地数据库文件

- 位置：`backend/chenji_hub.db`（在 `backend/` 目录启动后端时创建）
- 已被 `.gitignore` 忽略（`*.db`），不会提交到 GitHub。
- 本地与线上是**两份独立数据**，本地写的内容不会自动同步到线上。

## 7. 验证数据库状态

```bash
# 本地
cd backend && .venv/Scripts/activate
python -c "import sqlite3; c = sqlite3.connect('chenji_hub.db'); print(c.execute('select count(*) from articles').fetchone())"

# 线上（进入后端容器）
docker compose --env-file .env -f docker-compose.server.yml exec backend python -c "from app.database import engine; from sqlalchemy import text; print(engine.connect().execute(text('select count(*) from articles')).fetchone())"
```
